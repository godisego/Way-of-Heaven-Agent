## 1. 问题：为什么 LLM 不够用？

大模型（ChatGPT、Claude 等）很厉害，但它有两个根本缺陷：

| 缺陷 | 表现 | 类比 |
|---|---|---|
| **知识截止** | 它不知道训练截止日之后发生的事，也不知道你私人的典籍与笔记。 | 让一个读完大学的人回答「你昨晚写的日记第几页写了什么」 —— 他怎么可能知道？ |
| **幻觉** | 它会**自信地编造**不存在的细节、页码、数字、人名。 | 让一个人闭卷回答「《存在与虚无》第几页写的自欺」 —— 他大概率瞎编个页数，语气还特别自信。 |

**RAG 解决这两个问题的思路是一样的**：不让模型靠记忆答，而是**每次提问前给它一份「参考资料」**，让它照着资料答。

## 2. RAG 是什么？

**RAG = Retrieval-Augmented Generation**，检索增强生成。

拆开看：

```
R      Retrieval     检索     从你的资料库里找出和问题相关的内容
A      Augmented     增强     把找到的内容塞进 prompt
G      Generation    生成     LLM 基于被增强的 prompt 生成回答
```

### 类比（开卷考试）

没有 RAG 的 LLM 像**闭卷考试** —— 学生只能凭记忆答，所以会忘、会编。

加了 RAG 的 LLM 像**开卷考试** —— 发卷同时附一份参考资料，学生可以引用其中的具体段落，答错了也能查回来。

天道智能体的参考资料就是用户上传的典籍、笔记与书摘。

## 3. 总览：RAG 的两段流程

```
┌─── 离线：入库（一次性，文档上传时）──────────────────────────┐
│                                                            │
│  PDF / txt / md  ──►  切成小段（chunks）  ──►  每段变成向量（embedding） │
│                                       │                    │
│                                       ▼                    │
│                                  存进向量库                │
│                                                            │
└────────────────────────────────────────────────────────────┘

┌─── 在线：问答（每次提问都跑一遍）────────────────────────────┐
│                                                            │
│  问题 ──► 变成向量 ──► 在向量库找最像的 N 段 ──► 拼成 prompt │
│                                              │            │
│                                              ▼            │
│                                       LLM 基于这些段回答   │
└────────────────────────────────────────────────────────────┘
```

入库那段只跑一次（往后只是加新文档）。问答那段每次提问都跑。

**记住这两张图就够了**，下面所有概念都是它们的零件。

## 4. 概念逐个拆

### 4.1 Embedding —— 把"语义"翻译成"坐标"

**核心直觉**：**Embedding = 把一段文字变成一串数字（向量），让"意思相近的文字"在这串数字上"距离近"。**

把"想象成一个二维坐标"来理解：

```
       "存在先于本质"    "自欺与自由"      "今天天气不错"
            ●                  ●                  ●
            └─近               │
            ──────────────     │
                              远 ── ── ── ── ── ●
                                       "明朝海禁政策"
```

> 图是示意。真实 embedding 是 1536 维、3072 维这种高维空间，人脑画不出来，但**距离的直觉是一样的**。

**为什么可以用"距离"代表"意思像不像"？**
- Embedding 模型是这么训练出来的：把意思相近的句子放在相邻位置，不相关的放远。
- 所以"存在先于本质"和"自欺与自由"虽然字面不同，但语义相近 → 坐标相近 → 距离近。

> 一句话：**Embedding 是"语义的世界地图"，每个文本是一颗星，意思相近的星挨在一起。**

天道智能体里这个动作发生在：
```text
src/core/providers/openAICompatibleProvider.ts  调第三方 embedding API
src/core/providers/mockEmbeddingProvider.ts     不联网，用 SHA-512 假装成向量（纯演示）
```

### 4.2 向量库 & 余弦相似度 —— "找邻居"

**向量库 = 一个存了「文本 + 向量 + 元数据」的清单，能快速问"和这段文字最像的几段是什么"。**

最常见的"像不像"度量是**余弦相似度**（只看方向不看长度）。值域 [-1, 1]：1 = 完全同向，0 = 无关，-1 = 完全相反。

天道智能体里这份清单是个 JSON 文件：`data/indexes/chunks.json`。
真的生产里会换成 LanceDB、pgvector、Milvus 这类专用的向量数据库。

> 一句话：**向量库是按"语义"而非"字面"检索的搜索引擎。**

### 4.3 Chunking —— 为什么必须"切"

PDF 原文动辄上百页。**不能把整本典籍喂给 LLM**，因为：

1. LLM 有上下文窗口上限（典型几千到几万 token，都不够塞一本大部头）。
2. 答案往往只需要其中几段，塞太多反而稀释了关键信息。

所以要切成**小块（chunk）**—— 每块几百到上千字，带重叠（overlap）防止切到一句话中间。

天道智能体用的是**最简单的"按字符切 + 重叠"**（`chunkPages.ts`）：
- `TARGET_CHARS = 1200`：每块目标 1200 字符
- `OVERLAP_CHARS = 160`：相邻两块重叠 160 字符（防止一句话被切两半）

生产里更精细的切法：按段落、按标题、按版面分析、按语义切分 —— 视业务复杂度选择。

> 一句话：**Chunking 是为了把"大海"变成"小杯子"，让检索能精确捞到那一段。**

天道智能体里有个关键设计：**chunk 不跨来源单元**。PDF 的来源单元是一页，Markdown/TXT 的来源单元是章节或段落；因此 `[《周易》, 第42页]` 或 `[《存在主义笔记》, 自欺]` 都能定位回对应原文。

### 4.4 Prompt 组装 —— 怎么把材料喂给 LLM

检索完拿到 topK（比如 10 段）相关文本后，把它们**原样塞进 prompt**。典型长这样：

```text
[Source 1]
book: 存在与虚无
section: 第42页
cite_as: [《存在与虚无》, 第42页]
text: "自欺"是意识的内在结构，它必须知道真相才能掩盖真相……

[Source 2]
book: 周易白话
section: 需卦
cite_as: [《周易白话》, 需卦]
text: ……

问题：怎么理解"自欺"这个概念？
```

天道智能体的对应代码：`src/core/retrieval/retrieveContext.ts` 里的 `buildContext`。

> 一句话：**Prompt 组装是"开卷考试把参考资料发到学生手里"。**

### 4.5 Grounded Generation & 引用校验 —— 不让模型瞎说

**Grounded = 让模型"踩在地上"，基于给它的资料答，而不是凭记忆。**

光在 prompt 里说"请基于上述资料回答"还不够 —— 模型会**格式正确但内容虚构**（引用了一个它没看过的页码）。

所以天道智能体做了两层防护：

**第一层：system prompt**（`mentors.ts` 的 `buildMentorSystemPrompt`）
```text
你是三贤茶寮本尊。只能基于用户提供的 Sources 回答。
不要编造事实、页码、文件名或观点。
凡是引述思想或原文之处都必须带引用，格式为 [《书名》, 章节]；PDF 的章节位置写作“第N页”。
资料不足时，请明确说资料不足或"暂未入藏"。
```

**第二层：程序校验引用**（`citationPolicy.ts`）
```text
模型说：[《存在与虚无》, 第42页]

程序检查：
  - 这个书名在我们这次喂给它的 Sources 里吗？     YES
  - “第42页”这个来源位置在 Sources 里吗？          YES
  → 引用通过，保留

如果任意一条引用为 NO → 整组引用校验失败；系统强制重试一次，仍失败则挂警告。
```

**第二层是真正的护城河**。90% 的 demo RAG 死在"模型编页码"上，天道智能体没死就是因为这一层。

> 一句话：**Grounded 是"答题必须带出处"，programmatic 校验是"出处必须真实"——两者一起才能防住幻觉。**

### 4.6 Self-correct / Reflexion —— 失败了就重答

如果模型第一次回答格式不对（比如该引用没引用），天道智能体会**再问一遍**，并明确告诉它：

```text
上一次回答没有有效引用。请重新回答，并且每个事实性结论都必须
使用 [《书名》, 章节] 格式引用本轮 Sources 中给出的 `cite_as`。
```

如果第二次还失败，挂一个⚠️警告告诉用户"系统未能验证回答中的页码"。

**这是程序化 self-correct，不是完整 Agent 或 Reflexion**。完整 Reflexion 会记录结构化失败原因、跨轮保留可审计经验，并由评测验证是否真的减少错误。天道智能体目前只是校验失败后固定重试一次。

## 7. 术语表（高频词速查）

| 术语 | 一句话解释 |
|---|---|
| **LLM** | 大语言模型，ChatGPT/Claude 这种 |
| **Prompt** | 你发给模型的所有文字（系统提示 + 用户问题） |
| **System prompt** | 给模型的"角色定位 + 行为规则"，通常放在最前面 |
| **Token** | 模型处理文本的最小单位，大约 1 个汉字 ≈ 1.5 token，1 个英文单词 ≈ 1.3 token |
| **Context window** | 模型一次能"看见"的 prompt 最大长度 |
| **Embedding** | 把一段文本变成一串数字（向量） |
| **Vector / Embedding vector** | 上面的那串数字 |
| **Vector store / Vector DB** | 存向量并支持相似度检索的库 |
| **Cosine similarity** | 余弦相似度，常用的"像不像"度量 |
| **topK** | 检索返回最像的 K 条 |
| **Chunk** | 一段被切出来的文本块 |
| **Chunking** | 切块的行为 |
| **Overlap** | 相邻 chunk 之间的重叠字符，防切断 |
| **Hallucination** | 幻觉，模型编造不存在的细节 |
| **Grounded generation** | 让模型基于提供的资料回答 |
| **Citation** | 引用，这里专指 `[《书名》, 章节]`；PDF 位置使用 `[《书名》, 第N页]` |
| **RAG** | Retrieval-Augmented Generation，检索增强生成 |
| **Agent** | 能在循环里"思考-行动-观察"的 LLM 应用（见 Agent 文档） |
| **Reflexion / Self-correct** | 失败后反思重试的模式 |
