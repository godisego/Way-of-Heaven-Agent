# 八字盘面解剖：页面上每一项都是什么

这篇不是断命书，而是**排盘界面说明书的前一层**：使用指南告诉你按钮怎么点；本文告诉你每一行数据为什么存在、它在后续判断中承担什么角色。

全文使用一张虚构示例盘：

> **乙丑年　戊寅月　甲子日　丙寅时**
>
> 日主为甲木。示例只用于学习关系，不对应真实人物，也不据此下人生结论。

速查入口：[打开学习馆命理交叉速查](/learn#mingli-riyuan)。

## 一 · 先把八字看成一套正在运行的系统

可以暂时借用软件系统作比喻：

| 命理信息 | 软件系统比喻 | 真正定义 |
| --- | --- | --- |
| 四柱 | 四组带时间戳的系统快照 | 出生年、月、日、时各自对应的一组干支 |
| 天干 | 前端页面、公开 API | 显露在外、可直接看见的一层气 |
| 地支 | 服务器与运行环境 | 承载节令、时辰和内部力量的一层 |
| 藏干 | 服务器里的进程、数据库里的真实字段 | 每个地支内部所藏的一到三个天干 |
| 日主 | 当前登录用户 / 请求发起者 | 日柱天干；全盘关系的坐标原点 |
| 十神 | 相对于当前用户计算出的权限和关系标签 | 其他天干相对日主的五行生克与阴阳名称 |
| 月令 | 生产环境与当季系统负载 | 月柱地支；出生时最当令的季节力量 |
| 通根 | 前端功能背后有真实服务和数据支撑 | 某天干的五行在地支藏干中有根 |
| 大运 | 十年一个基础设施版本 | 从月柱顺逆排出的十年阶段 |
| 流年 | 当年流量、政策与天气 | 每年一换的干支外部环境 |

这个比喻只负责把层次分开，**不能代替命理规则**。例如天干并不真的等于网页，地支也不真的等于物理服务器；它们只是同样具有“外显层 / 承载层 / 内部实现层”的结构。

## 二 · 出生输入先经过什么处理

排盘不是把公历数字直接拼成八个字，而是按顺序经过几道确定性计算：

1. 读取公历出生日期、时间、性别与出生地经度。
2. 如果有经度，按经度差与均时差计算[真太阳时](/learn#mingli-zhen-taiyang-shi)。
3. 年柱以**立春**切年，不以元旦或春节初一切年。
4. 月柱以**节气**切月，不以农历初一切月。
5. 日柱按连续干支历日计算；23:00 后如何换日存在晚子时流派分歧。
6. 时柱由校正后的时辰和日干共同推出。

所以，出生在立春、节气、23:00 或时辰边界附近时，一点时间差可能改变某一柱。项目将这些步骤封装在 `src/core/user/baziCalculator.ts` 与 `src/core/user/solarTime.ts`，模型不参与计算。

## 三 · 四柱：同一张盘的四个观察窗口

| 柱 | 历法来源 | 传统观察窗口 | 在系统里的特殊作用 |
| --- | --- | --- | --- |
| 年柱 | 立春切换的年份干支 | 家族、祖辈、早年、外圈环境 | 年支给生肖；年干阴阳参与大运顺逆 |
| 月柱 | 节气切换的月份干支 | 父母、青年、社会环境 | 月支就是月令；大运从月柱排出 |
| 日柱 | 出生日干支 | 自身、伴侣、中年、内在生活 | 日干是日主；日支常称夫妻宫 |
| 时柱 | 出生时辰干支 | 子女、产出、晚年、收束方向 | 小运从时柱起排 |

“年柱代表 1-16 岁、月柱代表 17-32 岁”之类年龄段只是常见分段，不是精确计时器。柱位更像四个观察窗口，必须和十神、强弱及时间层一起看。

在示例盘里：

- 年柱 **乙丑**：乙是天干，丑是地支。
- 月柱 **戊寅**：寅还是月令，权重比普通地支更高。
- 日柱 **甲子**：甲是日主，即后续所有十神计算中的“我”。
- 时柱 **丙寅**：丙是外显天干，寅内部还藏有甲、丙、戊。

## 四 · 一柱内部到底装了什么

一柱不只有屏幕上最大的两个字。以示例的月柱“戊寅”为例，规则引擎保存：

| 字段 | 示例 | 干什么用 |
| --- | --- | --- |
| 干支 | 戊寅 | 这一柱的主标识 |
| 天干 | 戊 | 外显力量；相对甲日主为偏财 |
| 地支 | 寅 | 节令容器；本五行为木 |
| 藏干 | 甲、丙、戊 | 寅内部的本气、中气、余气 |
| 藏干十神 | 比肩、伤官、偏财 | 把内部力量翻译成人事关系 |
| 纳音 | 按六十甲子查得 | 古法补充标签；不参与本项目强弱记分 |
| 旬空 | 按本柱所在旬查得 | 古法参考项；不参与本项目强弱记分 |

点击整柱时，系统还会判断天干和地支之间是同气、得生、向下泄、盖头还是截脚，并说明天干是否在本支通根。代码在 `src/core/mingli/explainChart.ts`。

## 五 · 天干、地支、藏干为什么不能只看一层

假设一个产品页面写着“支持导出”，这是天干层：能力已经公开显露。但服务器没有导出服务、数据库也没有对应数据，这个功能就没有根；一遇到压力便容易失效。

反过来，服务器里已有完整导出服务，只是页面暂时没有入口，就像力量藏在地支里而未透干：它存在、可被条件引动，但平时不一定直接表现。

因此：

- **透干**关注“已经摆到台面上的是什么”。
- **藏干**关注“底层实际装着什么”。
- **通根**关注“台面上的力量有没有底层支撑”。
- **月令**关注“当前整个运行环境最支持哪种力量”。

继续阅读：[天干、地支与藏干](/learn/bazi-stems-branches)。

## 六 · 日主与十神：关系必须有参照物

十神不是十种固定物件，而是**相对于日主计算的关系名**。同一个戊土：

- 对甲木日主，甲克戊，是偏财。
- 对丙火日主，丙生戊，是食神。
- 对戊土日主，同五行同阴阳，是比肩。

这就像同一个账号在不同系统中可能是管理员、协作者或访客；对象没变，参照系变了，关系标签就变了。

示例甲日主的外显三干：乙为劫财、戊为偏财、丙为伤官。地支藏干也要逐个相对甲重新计算。继续阅读：[十神与强弱](/learn/bazi-ten-gods-strength)。

## 七 · 主卡片下面几行分别表示什么

### 五行计数

主卡的“金 0 木 3 水 1 火 1 土 3”是**四个天干 + 四个地支本五行**的八字可见层计数。它便于快速观察分布，但没有按藏干权重、月令旺衰、合冲刑害与调候加权。

因此，“某行数量为零”只表示可见层未出现，**不自动等于命里缺什么，也不自动推出吉凶**。

### 起运

起运表示出生后多久进入第一步大运。顺排者计算出生到下一个节的距离，逆排者计算到上一个节的距离，再按约定折算成年、月、日。

### 当前大运

大运每十年一步。页面显示当前所在的大运干支与起始年份；点击后会将大运天干和地支本气分别换算为相对日主的十神。

### 今年流年

流年是一年的干支，以立春切换。页面将它放在当前大运之内显示，因为判断顺序是“原局 + 大运 + 流年”，而不是只看某一年两个字。

### 小运

小运从时柱顺逆排，一岁一柱，主要用来补看尚未上大运前的幼年阶段。成年后通常退居参考。

继续阅读：[起运、大运、流年](/learn/bazi-luck-cycles)。

## 八 · 盘面总览里的派生判断

“盘面总览”还会从原始字段派生八组学习信息：

1. 日主与月令的旺相休囚死。
2. 月令、通根、天干生扶组成的强弱粗评。
3. 可见层五行计数。
4. 由强弱推导的喜忌大方向。
5. 透干与藏干加权后的十神组别偏重。
6. 当前大运与流年。
7. 命宫、身宫、胎元。
8. 每一步的简化边界和提醒。

这些结论都由查表与记分生成，不调用模型；但“确定性”只表示同样输入一定得到同样结果，**不表示简化模型等于完整真理**。

## 九 · 引擎算了、主卡却没有全部铺开的信息

为避免主卡变成一张密密麻麻的报表，以下信息通常在点击整柱、单字或总览后展开：

- 每柱天干十神、藏干与藏干十神。
- 纳音、旬空。
- 干支同气、得生、盖头、截脚与通根。
- 命宫、身宫、胎元。
- 天乙、文昌、驿马、桃花、华盖等神煞。
- 强弱记分的逐条理由。

神煞、纳音、旬空在本项目中只作补充，不进入强弱主算法。这体现一个重要原则：**展示一个字段，不等于让它拥有最高判断权重**。

## 十 · 读盘时的最短顺序

拿到任何一张盘，先按五问走：

1. 日主是谁，五行阴阳是什么？
2. 生在什么月令，环境支持还是消耗日主？
3. 四支里有没有根，台面上的干有没有底层支撑？
4. 哪些十神透出，落在哪一柱、哪一宫？
5. 当前大运与流年把哪部分原局关系引动出来？

先回答这五问，再谈格局、喜忌或具体事象。完整流程见：[七步读盘工作流](/learn/bazi-reading-workflow)。

> 边界：八字是传统文化解释框架，不是医学、法律、投资或人生决定工具。本项目禁止用排盘制造恐吓式确定性。
