# 天道智能体：当前架构与能力边界

> 工程案例。源码核对：2026-09-27。前置：[API 集成](/learn/api-integration)、[上下文与记忆](/learn/context-memory-engineering)。学习目标：画出请求、数据、模型和校验的边界，并指出哪些能力仍需实现。

## 一 · 当前是什么系统

这是本地优先的知识库应用，包含固定 RAG、受控 Agent 取证、会话持久化、滚动摘要和条件式联网回退。三贤默认由同一生成任务按角色组织，也可选择在席角色；它们不是三个独立运行的 Agent。

```text
浏览器：问者档 / 藏书 / 会话 / 学习馆
    ↓ Next.js API
请求校验、限流、服务端重算问者档、读取会话
    ↓ 最近消息 + 滚动摘要（帮助理解追问，不是典籍证据）
mode=rag → 固定分库检索 → 生成 → 引用与声口校验
其他模式 → 联网回退判定
    ├─ 库外非指定典籍问题 → 搜索网页 → 联网回答与来源标记
    └─ 其余 → Agent 工具循环 → Evidence Ledger → 生成与校验
    ↓ 保存消息、引用、轨迹 → 返回界面
```

普通 JSON 入口见 `src/app/api/chat/route.ts`；流式入口见 `src/app/api/chat/stream/route.ts`。两条入口分别有自己的编排代码，不能仅凭一个入口的测试断言另一条完全相同。

## 二 · 数据从哪里来

| 数据 | 当前保存与使用位置 | 边界 |
| --- | --- | --- |
| 文档与来源单元 | `data/app.json`、`data/documents/` | PDF 页码是真页；Markdown/TXT 为来源单元编号 |
| 向量索引 | `data/indexes/chunks.json` | 入库写本地；换 embedding 模型需重建 |
| 会话、消息、引用、轨迹 | `sessionStore.ts` → 本地 JSON | 支持恢复、改名、删除；不是跨用户记忆服务 |
| 会话摘要 | `contextBuilder.ts` → session | 滚动压缩早期消息；可能遗漏或失真 |
| 问者档 | 用户档案存储与服务端准备函数 | 生辰换算由代码完成；不等同模型长期记忆 |
| Provider 设置 | 服务端配置文件与环境变量 | 密钥不应进入客户端代码或 Git |

入库按校验、内容哈希去重、解析来源单元、切块、embedding、写索引推进；失败状态保留原因，可重试。它仍是请求内工作，没有完整后台任务调度。

## 三 · RAG、Agent 与联网不是同一条证据链

固定 RAG 用 `searchChunksForMentors` 大召回，再按 `mentors.ts` 声明的思想传统分配各角色可引用的证据。Agent 则通过 `search_library`、`read_source_unit`、`ready_to_answer` 动态收集证据，台账记录来源，再进入生成。

引用校验核对书名、来源位置与角色的来源范围；声口校验检查格式和预设角色规则。固定 RAG 最多定向重试一次，Agent 最多两次。校验未清时可能附警告交付，**来源有效不代表每句话获得语义支持，`completed` 也不代表事实全部正确**。

联网回退在 `webFallback.ts` 中使用单独的分数门槛，指定库内书的引用问题被排除。网页摘要及模型知识生成不经过同一套典籍引用台账校验；搜索失败也可能返回标明未联网核实的模型回答。来源标记应让读者知道本轮用了哪一种证据，不能把网页链接等同已验证结论。

## 四 · 已有控制与未完成边界

| 方面 | 已有 | 仍需注意 |
| --- | --- | --- |
| 工具 | 三个白名单工具、参数校验、限次、文档 ID 范围 | 文档范围不是完整多租户鉴权 |
| 时间与步数 | 默认最多六次注册表调用；调度请求 45 秒；循环边界检查 90 秒预算 | 不是全请求 90 秒硬截止；工具等待超时不保证底层取消 |
| 相关性 | 引用问题词面检查；联网回退独立分数门槛 | 未实现通用 BM25 混合检索或 rerank；分数需随模型校准 |
| 会话 | 最近消息、滚动摘要、持久化轨迹 | 未实现经用户确认、可逐项管理的跨会话长期记忆 |
| 运维 | 部分 API 限流、诊断接口、自动测试 | 没有完整多用户身份隔离、分布式限流和生产成本硬预算 |
| 文档 | 来源坐标和原文预览 | 暂无完整 OCR、表格及版面恢复 |

具体停止条件与实现差异见 [工具循环案例](/learn/agent-loop)。

## 五 · 云端与本地的边界

`VECTOR_BACKEND=supabase` 只切换向量检索读取后端。`sync:supabase` 可同步文档、来源单元、向量与原文件快照；它**不会自动迁移本地会话、设置、所有写入和 API 路径**。当前部分入口还会检查本地索引，所以不能仅改变量就宣称完成无状态部署。

本地 JSON 适合受保护的单进程学习环境，没有数据库事务、跨进程锁或租户隔离。公网部署、横向扩容与云端持久化是另一项工程，需逐项迁移和验证，见 [部署课](/learn/production-deployment)。配置外部模型与搜索服务后，相关请求数据会发送给这些服务；“本地保存”不等于“数据从不外发”。

## 六 · 架构核验练习

画出“同一会话第二轮追问”的路径，分别标注会话上下文、典籍证据和外部请求。然后解释：为什么调度模型能读到历史对话，却不能拿历史回答当作本轮典籍来源？为什么切到 Supabase 向量检索不等于会话也上云？

**参考答案**：历史通过 `conversationContext` 帮助理解追问；可引用证据来自当前检索或台账。会话摘要可能压缩错误，不能替代来源。向量存储和会话存储是不同接口，当前后者仍写本地 JSON。

**通过标准**：图区分三类数据，指出至少两个未实现边界，并能用对应源码核对，而非照抄“完整 Agent”的组件列表。
