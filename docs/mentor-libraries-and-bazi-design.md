# 命理如何进入三贤：材料分发与校验边界

> 当前实现核对：2026-09-28。前置：[七步读盘](/learn/bazi-reading-workflow)、[架构总览](/learn/architecture)。早期 v1 设计已实施的部分应以当前源码为准，本篇不再作为待评审施工计划。

## 一 · 规则计算与模型解释

出生输入通过 `baziCalculator.ts` 计算四柱、藏干十神、岁运等，再由 `chartBrief.ts` 组织材料。模型负责表述和讨论，不能把生成文本当作规则计算结果，也不能由计算可重复就断言现实预测有效。

十神规则改动后，旧问者档的派生排盘按规则版本重算；出生输入保留。用户先前上传或入库的讲义副本不会随仓库文件自动替换，使用时应核查其版本。

## 二 · 三种角色使用范围

| 角色 | 分发方式 | 应遵守的回答边界 |
| --- | --- | --- |
| 老胡 | 较完整的命理简报 | 解释规则与条件，不凭空算盘或保证事件 |
| 玄 | 气机与节奏表达的简报 | 区分比喻与证据，不把比喻当精确算法 |
| 李 | 现实背景，不分发命理简报到其角色块 | 讨论处境与选择，不使用命理术语 |

源码见 `src/core/mingli/chartBrief.ts` 与 `src/data/mentors.ts`。默认多个角色共享一次模型上下文；角色块的不同**不等于模型看不到其他块，也不是隐私隔离**。真正隔离需要分别构建受控请求和独立权限边界。

## 三 · 典籍来源范围

`mentors.ts` 的 traditions 字段定义角色可用的思想传统。固定 RAG 分配检索证据，Agent 路径通过工具和台账获取来源；最终引用按角色和来源坐标检查。标签解决角色来源范围，不解决多用户鉴权。

未标注资料及共享标签的处理以当前配置为准；不能靠人设禁止语句阻止数据泄漏。敏感材料应在进入模型前按真实用户权限过滤，而不是仅在回答后检查。

## 四 · 检查通过意味着什么

引用校验确认坐标与角色范围；声口校验检查格式及预设规则。通过不证明引用在语义上支持每句话，也不证明命理判断有效。固定 RAG 与 Agent 有不同的限次修正策略，见[工具循环](/learn/agent-loop)。

## 五 · 练习与评价

画出“出生输入 → 规则计算 → 角色材料 → 共享模型 → 校验”的路径，圈出两类边界：确定性换算与生成解释；角色分工与真正的数据访问权限。

**参考答案**：十神由规则计算；叙述由模型生成；不同角色块仍在共享上下文内。若李出现命理用语，应定位材料、提示词与校验路径，不能推断已经存在独立模型或物理隔离。能说明这三点并指向源码，才完成本课知识检查。
