# AI 学习五层地图

这张地图是整个 AI 与 Agent 学径的共同坐标。遇到新名字，先问它解决什么问题、属于哪一层，再决定是否值得使用。阅读顺序是世界观 → 技术树 → 模型原理 → AI Engineering → 产品思维；做项目时则从第五层的用户问题出发，在各层之间往返。

> 本轮课程核对日期：2026-09-21。Jev、协议与服务能力会演进；课程区分稳定原理、官方当前说明和本项目已实现能力。

## 一 · 五层各回答什么

| 层 | 核心问题 | 起步讲义 | 学完交什么 |
| --- | --- | --- | --- |
| AI 世界观 | AI 到底在解决什么问题？ | [从感知到行动](/learn/ai-worldview) | 拆解一个产品的输入、表征、预测、决策与行动 |
| AI 技术树 | 新概念应该放在哪个抽屉？ | [技术树与概念归位](/learn/ai-technology-map) | 给十个概念标上方法、领域、模型、架构或协议标签 |
| 模型原理 | 模型怎样学会、怎样生成？ | [从 Token 到推理](/learn/transformer-mechanics) | 解释 Attention、训练与推理，并画出一次生成过程 |
| AI Engineering | 怎样做成可运行、可恢复、可评测的系统？ | [上下文与记忆](/learn/context-memory-engineering) | 一张系统图、一条执行轨迹、一份失败回归集 |
| AI 产品思维 | 谁为什么结果付钱？ | [Solution / FDE 交付](/learn/ai-solution-delivery) | 带基线、验收条件与收益测算的试点方案 |

## 二 · 贯穿全程的两个案例

**客户投诉分流**：客户文本是输入；模型从文本预测投诉类别与紧急程度；业务代码根据代价和权限决定转哪个队列；工单 API 执行；处理结果回流评测。Jev 可以作为其中的决策模块，LLM 可以生成回复，规则控制升级和写入。是否需要 Agent，要看是否需要根据工具反馈动态调查，不能由“用了 AI”推断。

**天道茶寮**：出生资料交给规则计算；典籍进入检索；模型组织语言；“循迹”开启时由 Agent 循环选择查证动作，关闭时走 RAG 路径；回答还经过引用与声口校验。三贤是共同生成的三个角色，不是三个独立 Agent。源码与目标架构的差别见 [全景图](/learn/ai-agent-panorama)。

这两个案例能提醒你：模型、软件控制流与业务规则共同决定产品行为。任何单个模型都不等于完整产品。

## 四 · 以后分析 AI 产品的固定九问

| 问题 | 要找的证据 |
| --- | --- |
| 模型是谁，适合做什么？ | 版本、任务评测、生成或决策接口 |
| 上下文从哪里来？ | 系统指令、用户输入、会话摘要、可用预算 |
| 知识从哪里来？ | 训练知识、实时查询、RAG 来源与权限 |
| 工具怎样调用？ | 参数契约、校验、执行者、授权与副作用 |
| 状态怎样保存？ | 会话状态、任务进度、checkpoint 与版本 |
| 失败怎样恢复？ | 超时、重试、幂等、人工接管与停止条件 |
| 结果怎样评估？ | 代表性测试集、标准答案、失败类别、线上回流 |
| 成本是多少？ | 每个成功任务的模型、工具、人工和运维成本 |
| 延迟是多少？ | 首响应、完整任务、p50 / p95、超时占比 |

## 五 · 每层一次验收

1. 世界观：把“读投诉并转人工”拆成五种功能。说明哪一步是预测、哪一步真正执行。
2. 技术树：给 Transformer、NLP、RAG、Agent、MCP、Jev、SFT 分类；允许一个概念有多个轴的标签。
3. 模型原理：用自己的话说明 Q/K/V 的分工；解释为什么一次聊天不等于重新训练。
4. 工程：设计一个工具写入成功但响应超时的恢复流程；指出重试为什么可能重复执行。
5. 产品：计算净收益，并给出即便模型准确率高仍应停止试点的理由。

**参考答案要点**：文本接收属于感知，紧急程度估计属于预测，升级策略属于决策，工单 API 才是行动；RAG 与 Agent 是架构层，MCP 是协议层；Q 用于查询、K 用于匹配、V 提供聚合内容，训练更新参数而常规推理不更新；写入需幂等键与查单恢复；人工复核、误判损失、部署成本或低采用率可能使净收益为负。更完整的答案在各篇课后。

## 六 · 新技术怎样进入学习馆

新增内容必须回答：官方来源是什么、核对日期是什么、放在哪一层、替代或补充哪个环节、在本项目有没有实现、怎样验证它带来收益。Jev 放在模型任务与输出的比较中，MCP / A2A 放在工程集成中，Skills 放在复用任务知识的工程机制中。

技术选型可以组合。Workflow 与 Agent 的控制权划分可参考 [Anthropic 的工程说明](https://www.anthropic.com/engineering/building-effective-agents)；本地图的五层顺序是学习组织方式，不声称是学术界唯一分类。
