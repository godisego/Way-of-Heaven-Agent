# AI 世界观：AI 到底在解决什么问题

> 位置：五层地图第 1 层。先读 [AI 学习地图](/learn/ai-learning-map)，再用本篇的方法观察你每天使用的产品。

## 学习目标

- 用一句话说清 AI 产品帮助谁完成什么任务。
- 用“感知 → 表征 → 预测 → 决策 → 行动”拆解一个系统。
- 分清模型生成的内容、程序执行的动作、环境返回的事实。
- 遇到失败时，指出问题发生在哪一步，而不是只说“模型不聪明”。

## 一 · 先看任务，再看名词

AI 研究与应用的一项核心工作，是让机器根据输入和已有知识完成识别、预测、推理、选择或执行等任务。机器学习通过数据学习规律，深度学习进一步学习多层表征；但 AI 也包含搜索、规划、规则推理等方法。[Deep Learning：第 1 章](https://www.deeplearningbook.org/contents/intro.html)

学习馆统一使用这条观察链：

```
感知 → 表征 → 预测 → 决策 → 行动
 ↑                            │
 └────── 环境反馈（如果有）─────┘
```

**这是按功能分析系统的视角，不是所有 AI 产品都必须依次经过的五个软件模块。** 分类器可能只输出预测，由人做决策；检索器可能只找到相关信息；一个神经网络也可能同时承担多种功能。实际流程还会分支、并行、循环。

| 功能 | 要问什么 | 日常例子 |
|------|----------|----------|
| 感知 | 系统拿到了什么输入与观察？ | 用户文字、图片、数据库查询结果 |
| 表征 | 信息被组织成什么计算形式？ | Token ID、向量、结构化订单、任务状态 |
| 预测 | 系统估计了什么未知量？ | 下一 Token 的分布、文档相关性、故障概率 |
| 决策 | 根据目标和约束选择什么？ | 继续检索、给出回答、转交人工 |
| 行动 | 哪个输出真正产生了效果？ | 显示回答、发起查询、更新记录 |

这里的“决策”可能由模型、明确的程序规则或人完成。预测“这条记录可能有错”和决定“修改这条记录”是两回事。

## 二 · 把一个聊天模型放回链路

假设用户输入：“用两句话解释什么是 RAG。”先看常见自回归文本模型的简化过程：

```
用户文字
  → Tokenizer：切成 Token，并映射到 ID
  → Embedding 与位置信息：形成输入表示
  → 多层 Transformer：更新表示
  → 输出下一 Token 的概率分布
  → 解码策略：选择一个 Token
  → 把新 Token 接回序列，继续生成
  → 到结束标记或其他停止条件，显示回答
```

这是常见文本生成机制的简图，不代表每个聊天产品的完整实现。产品还可能加入检索、工具、内容处理和状态管理。[Hugging Face：Text generation](https://huggingface.co/docs/transformers/en/llm_tutorial)

放回观察链：接收输入属于感知；Token 与向量属于表征；下一 Token 分布属于预测；选择 Token 是局部生成决策；把回答显示给用户是一种输出行动。

**“预测下一 Token”描述计算机制，不等于“只会背句子”，也不等于“生成的事实经过核验”。** 生成质量必须放回具体任务评估。看到一句流畅的回答，只证明系统生成了文本。

## 三 · 把 Agent 放回链路

现在目标变成：“从学习馆中整理 3 篇适合 Agent 初学者的课程，检查链接，并给出顺序。”一个具备检索工具的 Agent 可以这样运行：

```
目标：找 3 篇入门课程，链接有效，顺序有理由
  → 获取课程目录
  → 将已找到的课程、待核查事项存入任务状态
  → 判断缺少什么信息
  → 提出工具调用：读取课程 / 检查链接
  → 运行系统校验参数与权限，执行工具
  → 读取成功结果或错误，更新任务状态
  → 继续查询、调整方案，或输出结果
  → 达成条件 / 到预算上限 / 需要人工介入时停止
```

Agent 的关键是能结合运行中的反馈选择后续步骤。LLM 往往提供语言理解与动作建议，运行系统负责执行、状态、预算和停止条件。固定步骤的 Workflow 也能使用同一个 LLM；两者可以在一个产品里组合。[Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

模型输出 `read_course({slug: "agent-walkthrough"})` 是**调用意图**。工具返回课程正文才是执行结果。模型说“链接有效”也不能代替真实检查记录。

## 四 · 同一个失败，可能来自不同环节

假设 Agent 最终给出了不存在的课程链接：

| 环节 | 可能的原因 | 先检查什么 |
|------|------------|--------------|
| 感知 | 读到过期目录 | 目录来源与更新时间 |
| 表征 | 把课程标题错当成 slug | 字段结构和转换规则 |
| 预测 | 生成了看起来合理的地址 | 是否要求使用返回的真实字段 |
| 决策 | 未检查链接便结束 | 完成条件和工具调用轨迹 |
| 行动 | 检查工具失败却被当成成功 | 工具状态、错误信息与重试结果 |

这张表是诊断练习，不是对本项目现有错误的断言。其目的在于训练一个习惯：**先定位输入、过程和证据，再决定该改模型、提示词、工具还是业务流程。**

## 五 · 产品经理、Solution、FDE 各看什么

面对同一套课程推荐系统，三个视角可以共享一张图：

- AI 产品经理：用户是否因此更快找到合适的第一课？推荐错一次的影响有多大？
- AI Solution：目录、模型与现有平台怎么连接？哪一步用固定规则就足够？
- FDE：如何在真实数据、权限和运行环境里交付？失败能定位和恢复吗？

它们不是三个互斥岗位清单，而是从价值、方案到落地的不同观察重点。学习这条链是为了让三种讨论能互相接上。

## 六 · 常见误区

| 说法 | 更准确的理解 |
|------|--------------|
| 所有 AI 都是聊天模型 | 识别、检索、推荐、控制等系统可能不生成对话 |
| AI 必须走完五个独立模块 | 五步是功能视角，实际系统可能合并或只覆盖部分功能 |
| 有聊天界面就是 Agent | 要看运行中是否根据目标与反馈决定后续步骤 |
| 模型说完成就代表完成 | 完成应由结果、工具返回和验收条件支持 |
| 加强 Prompt 就能修好所有失败 | 数据、权限、工具和状态管理都可能是原因 |

## 七 · 练习与参考答案

### 练习

1. 一个系统把照片分成“有猫/无猫”，由人决定是否保留照片。它覆盖了哪些功能？
2. 一个助手说“我已经查了库存”，但没有工具调用记录。你能确认哪些事实？
3. 一套程序按“检索 → 生成 → 格式校验”固定执行，失败时固定重试一次。仅凭这些信息，应该先把它归为什么？
4. 用本篇五步拆解“从学习馆选出 3 篇 Agent 入门课”，写出至少两个可检查的完成条件。

### 参考答案

1. 照片输入是感知；像素及中间特征是表征；类别分数是预测。是否保留由人决策。不要为了凑齐五步而虚构一个自动删除模块。
2. 只能确认它生成了这句话。需要查询日志、工具返回及时间信息，才能支持库存已查到的结论。
3. 先归为含 LLM 的固定 Workflow。重复调用本身不证明模型在自主选择后续步骤。
4. 示例：读目录 → 保存标题与 slug → 判断课程与入门需求的匹配程度 → 选择并检查 3 篇 → 输出顺序。完成条件可以是“3 个链接均存在”“每篇给出先修要求及排序理由”。
