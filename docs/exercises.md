# 作业练习册

光看讲义不动手 = 没学。这份练习册有 5 道题，从"跑通环境"到"改一行代码"到"自己设计 prompt"——每道题都有明确的验收标准，做完能自己判断对不对。

> 这不是考试，是练习。做错了没关系——每道题的"卡住了？"都给了提示。

## 作业 1 · 跑通环境（入门）

**目标**：让天道茶寮在你本机能跑起来，三贤能对谈。

**步骤**：
1. `git clone` 项目
2. `npm ci` 安装依赖
3. `cp .env.example .env.local`（不填 key 也行）
4. `npm run seed:all` 入库典籍
5. `npm run doctor` 确认索引状态
6. `npm run dev` 启动
7. 打开 `http://localhost:3000`，配置聊天供应商（右下齿轮）
8. 问三贤一个问题，得到回答

**验收标准**：
- [ ] `npm run doctor` 显示索引非空（>200 条）
- [ ] 三贤回答不是"材料不足"
- [ ] 回答里有至少一处 `[《书名》, 章节]` 格式的引用

**卡住了？**
- 索引为空 → 忘了跑 `npm run seed:all`
- 回答说"材料不足" → 索引没建好，检查 `data/indexes/chunks.json` 是否存在
- 回答报错"缺 CHAT_API_KEY" → 齿轮里没配聊天供应商

## 作业 2 · 检索实验（入门）

**目标**：用 `/api/search` 观察向量检索的行为，理解 mock vs real 的差异。

**步骤**：
1. 确认当前是 mock 还是 real embedding（`npm run doctor` 看）
2. 用 curl 搜以下 5 个问题，记录返回的 top 3 score：
   - "天干地支是什么"
   - "什么是自由意志"
   - "无为而治"
   - "伤官见官"
   - "量子力学"（库里没有的内容）
3. 如果当前是 mock，配一个 real embedding key，跑 `npm run reindex:embeddings`
4. 重新搜同样 5 个问题，对比 score 变化

**验收标准**：
- [ ] "量子力学"的 top 3 score 都很低（<0.2）
- [ ] "天干地支"的 top 1 来自命理教材（不是哲学书）
- [ ] Real embedding 的排序比 mock 更准（命理问题排在哲学前面）

**记录表**：

| 问题 | Mock top1 score | Mock top1 source | Real top1 score | Real top1 source |
|------|----------------|-----------------|----------------|-----------------|
| 天干地支 | | | | |
| 自由意志 | | | | |
| 无为而治 | | | | |
| 伤官见官 | | | | |
| 量子力学 | | | | |

**卡住了？**
- 不想花钱用 real embedding → 可以只做 mock 部分，理解概念即可
- curl 命令不会写 → 看讲义里的示例

## 作业 3 · 改一行代码（进阶）

**目标**：修改 Agent 循环的最大步数，观察行为变化。

**背景**：Agent 默认最多循环 6 步（`MAX_STEPS=6`）。这个数字太大模型可能反复搜索烧 token，太小可能没搜够就停。

**步骤**：
1. 在 `src/core/agent/orchestrator.ts` 找到 `MAX_STEPS` 定义
2. 改成 `MAX_STEPS=3`
3. 问三贤一个复杂问题（如"伤官见官在不同格局下有什么不同表现"）
4. 观察执行轨迹——是不是 3 步就停了？回答质量有没有下降？
5. 再改成 `MAX_STEPS=10`，问同一个问题
6. 观察是否搜了更多次？回答有没有更好？

**验收标准**：
- [ ] 能找到 `MAX_STEPS` 的定义位置
- [ ] MAX_STEPS=3 时，执行轨迹显示 3 步后停止（停止原因="步数上限"）
- [ ] 能用自己的话解释"步数上限太小的风险"

**卡住了？**
- 找不到文件 → `rg "MAX_STEPS" src/core/agent/`
- 看不到执行轨迹 → 对谈界面开"循迹"开关

## 作业 4 · 设计 Prompt（进阶）

**目标**：为三贤写一段新的系统提示词，让模型按你设定的风格说话。

**背景**：当前三贤的 prompt 在 `src/data/mentors.ts`。你要试着改其中一个贤者的设定。

**步骤**：
1. 读 `src/data/mentors.ts`，找到三贤的 system prompt 定义
2. 选一个贤者（建议老胡），修改他的：
   - 说话风格（如从"直给"改成"委婉含蓄"）
   - 能做/不能做的边界
   - 输出格式
3. 重启 dev server，问同一个问题（如"我最近工作不顺怎么办"）
4. 观察：老胡的回答风格是不是变了？变好了还是变差了？
5. 对比修改前后的回答，思考：prompt 的哪一处改动导致了风格变化？

**验收标准**：
- [ ] 能找到三贤 prompt 的定义文件
- [ ] 修改后重启服务不报错
- [ ] 能指出"修改前 vs 修改后"的回答差异
- [ ] 能说清楚哪一处 prompt 改动导致了差异

**卡住了？**
- 不知道改什么 → 试着把老胡的"直给"改成"用古文回答"，看模型怎么变
- 回答跑偏 → 检查是不是删了"不能编造出处"的负面约束

## 作业 5 · 抓一次幻觉（工程）

**目标**：主动制造一次模型幻觉，观察引用校验如何拦截。

**背景**：幻觉 = 模型编造不存在的内容。引用校验 = 程序检查回答里的引用是否真的在检索到的段落里。

**步骤**：
1. 问三贤一个"库里肯定没有但容易编"的问题，如：
   - "《周易》第 42 卦说的量子纠缠是什么"（库里有周易但没量子纠缠）
   - "萨特在《存在主义笔记》第 7 页怎么讨论区块链"（库里有存在主义笔记但没有区块链）
2. 观察三贤的回答：
   - 如果三贤说"暂未入藏" → 引用校验+prompt 生效了
   - 如果三贤编了内容 → 模型幻觉了
   - 如果三贤编了引用 → 看引用校验有没有拦住（看 pipeline 字段）
3. 如果你成功抓到幻觉，开"循迹"模式重问，对比 RAG 模式和 Agent 模式的差异

**验收标准**：
- [ ] 能构造一个"容易诱发幻觉"的问题
- [ ] 三贤要么说"暂未入藏"，要么编了内容被校验拦住
- [ ] 能解释"prompt 约束"和"程序校验"分别防了什么

**卡住了？**
- 三贤没编 → 恭喜，prompt 和校验生效了！换一个更刁钻的问题
- 三贤编了且没被拦 → 可能是校验逻辑有漏洞，值得提 issue

## 附加题 · 上传自己的文档

如果你有自己的 `.md` 或 `.txt` 笔记想给三贤当典籍：

1. 在对谈界面找到上传入口
2. 上传你的文档（支持 .md / .txt / .pdf）
3. 等待入库完成（看状态变成 "indexed"）
4. 问一个只有你文档里有的内容
5. 检查三贤能不能引用你的文档回答

**验收标准**：
- [ ] 文档状态变成 "indexed"
- [ ] 三贤能引用你上传的文档内容
- [ ] 引用格式是 `[《你的文档名》, 章节]`
