# AI 技术地图：把概念放回正确抽屉

> 位置：五层地图第 2 层。前置：[AI 世界观](/learn/ai-worldview)。

## 学习目标

- 说明 AI、机器学习、深度学习之间的包含关系。
- 区分“怎么学习”“用什么网络”“处理什么任务”“怎样搭建系统”四类问题。
- 正确定位 LLM、RAG、Agent、Workflow、Prompt 与 Memory。
- 遇到一个新缩写，先查全称和来源，再判断它替换或补充了哪个环节。

## 一 · 技术地图需要多个维度

“机器学习、NLP、计算机视觉、Agent”经常画在同一棵树里，但它们的分类标准不同。机器学习是一类方法，NLP 与视觉是任务领域，今天讨论的 LLM Agent 通常是一类运行系统。它们有大量交叉。

先保留清楚的包含关系，再把其他轴分开展示：

```
方法视角
Artificial Intelligence（AI）
├─ 搜索、规划、知识表示与规则推理等方法
└─ Machine Learning（机器学习）
   ├─ 线性模型、树模型等
   └─ Deep Learning（深度学习）
      ├─ CNN
      ├─ RNN / LSTM
      ├─ Transformer
      └─ 其他神经网络架构及混合架构

学习信号视角（可与上面的方法交叉）
监督学习 / 无监督学习 / 自监督学习 / 强化学习

任务领域视角（可同时使用多类方法）
NLP / 计算机视觉 / 语音 / 推荐 / 机器人 / 多模态等

应用系统视角（可组合）
模型调用 / RAG / Tool Calling / Workflow / Agent
```

深度学习属于机器学习；它可以用于文本、图像、语音等不同领域。上图是入门索引，不是穷尽所有研究分支的严格分类法。[Deep Learning：第 1 章](https://www.deeplearningbook.org/contents/intro.html)

## 二 · 先区分“学习方式”和“网络架构”

| 学习方式 | 信号从哪里来 | 示例 |
|----------|--------------|------|
| 监督学习 | 已提供的输入与目标标签 | 根据已标注工单学习分类 |
| 无监督学习 | 数据本身的结构 | 将相似工单聚类 |
| 自监督学习 | 从原始数据构造预测目标 | 给定前文，预测下一个 Token |
| 强化学习 | 行为带来的奖励信号 | 在环境中学习能提高长期回报的策略 |

自监督学习与无监督学习的术语边界在不同教材中有所差异。这里单列，是为了说清 LLM 预训练的目标来自哪里。奖励也不一定来自人：测试通过与否、环境得分或模型反馈都可能提供训练信号。

CNN、RNN/LSTM、Transformer 则回答“网络怎样组织计算”。同一类架构可以用多种学习方式训练，不应该把深度学习当成与监督学习互斥的分支。

LLM 常见做法是先预训练，再用监督微调或偏好相关方法进行后训练。详细原理见 [Transformer 与模型训练机制](/learn/transformer-mechanics)。[Hugging Face：How do Transformers work?](https://huggingface.co/learn/llm-course/chapter1/4)

## 三 · 模型领域与内部组件也要分开

| 概念 | 它属于哪个维度 | 解决什么问题 |
|------|----------------|--------------|
| NLP | 任务领域 | 处理、理解或生成自然语言 |
| Computer Vision | 任务领域 | 处理图像与视频相关任务 |
| LLM | 模型类别 | 建模语言序列，可用于多类语言任务 |
| Transformer | 网络架构 | 通过注意力等计算更新序列表示 |
| Tokenizer | 输入与输出处理组件 | 在文本与 Token ID 之间转换 |
| Embedding | 表示方法；也可指专用模型输出 | 将离散或复杂输入表示为向量 |
| Attention | 网络中的计算机制 | 依据相关程度汇总其他位置的信息 |
| Pretraining / Post-training | 训练阶段 | 学习通用规律、调整目标行为 |
| Inference | 运行阶段 | 使用模型参数计算当前输入的输出 |

**LLM 不等于 NLP 全部；Transformer 也不只用于 LLM。** 例如视觉 Transformer 将图像块作为输入。多模态模型会跨越语言与视觉领域，这不要求我们给它选一个唯一抽屉。[Vision Transformer 原始论文](https://arxiv.org/abs/2010.11929)

还可以增加“任务与输出”的观察轴：有的模型面向开放文本生成，有的面向分类、打分或结构化决策。**这不是互斥、完整的模型分类；LLM 同样能执行分类与决策任务。** TypeSafe 在 2026 年 9 月发布的 Jev 应放在这个轴上理解：官方定位强调类型约束下的概率决策，“System One Models”是该厂商使用的名称。它不是与机器学习平级的新学科，也不是完整 Agent。第二层先学 [分类与概率基础](/learn/classification-probability-basics)；完成工程评测课后，可选读 [Jev 与决策模型](/learn/jev-decision-models)。[TypeSafe 官方发布](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## 四 · RAG 与 Agent 应该放在哪里

RAG（Retrieval-Augmented Generation，检索增强生成）是一种**应用架构模式**：检索外部信息，把相关内容提供给生成模型。经典研究还联合训练了检索与生成组件，但“使用 RAG”不意味着必须训练新模型。[RAG 原始论文](https://arxiv.org/abs/2005.11401)

```
RAG：问题 → 检索 → 整理证据 → 生成回答

Agent：目标与观察 → 决定下一步 → 执行工具
                         ↑             │
                         └── 结果反馈 ──┘
```

学习馆使用的“Agent”主要指**基于 LLM 的运行系统或软件架构**。它把模型、上下文、工具、状态、执行控制等组合起来。它可能用 RAG 找知识，也可能完全不需要知识库。更广义的 AI 研究中的 agent 不限于 LLM。

Workflow 强调由程序规定执行路径；Agent 强调模型根据运行中的信息选择后续步骤。一个 Workflow 的某个节点可以是 Agent，一个 Agent 的工具也可以执行固定 Workflow。它们是组合方式，不是技术先进程度的排名。[Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

## 五 · 应用架构里的常用抽屉

| 概念 | 应放在哪里 | 不应误认为什么 |
|------|------------|----------------|
| Prompt | 当前调用的指令与示例 | 写一句话就在更新模型参数 |
| Context | 当前调用能使用的信息 | 整个数据库都自动在模型脑中 |
| Memory | 保存、检索、更新信息的机制 | 一定需要向量库，或无限的上下文窗口 |
| Tools | 由运行系统执行的能力接口 | 模型提到工具就已执行 |
| Planning | 分解目标与选择步骤的策略 | 必须提前写一份完整长计划 |
| RAG | 检索与生成的组合模式 | 新模型、向量数据库或准确性保证 |
| Workflow | 执行步骤与分支的编排 | 只能做简单工作 |
| Agent | 根据目标与反馈循环运行的系统 | 某个大模型的别名 |
| Evaluation | 检查结果和行为的方法 | 让模型给自己打个分就足够 |
| Observability | 记录和定位运行过程的能力 | 存了聊天文本就能解释所有错误 |

后半张表是工程上的责任划分。记忆与上下文的具体设计见 [上下文与记忆工程](/learn/context-memory-engineering)。

## 六 · 用一个具体方案练归类

需求：“帮助学习者找到与当前问题相关的原文，回答并给出引用。”

```
用户目标：更快找到可核对的知识
任务领域：自然语言问答与信息检索
模型：生成模型 + 可选的检索 Embedding 模型
应用架构：RAG
执行路径：固定检索一次可以是 Workflow
动态行为：若模型能决定补查或换工具，可加入 Agent 循环
质量机制：引用核验、无证据时的处理、评测样本
运行机制：状态、日志、预算、错误恢复
```

你现在就能回答“RAG 是 AI 吗”：它是 AI 应用中的架构模式，使用模型和检索系统，但它自身不是一种模型类别。

## 七 · 看到新名词时的四步核查

1. 找到完整名称、作者或维护方，以及原始论文或官方文档。缩写不明确时保留不确定性。
2. 判断它属于学习方法、网络架构、任务领域、应用模式、协议、工具还是产品名称。
3. 指出它改变了哪条输入输出关系：预测什么、执行什么、与谁交换什么信息。
4. 问它解决现有系统中的哪个问题，并找能证明改善的评测。

只有名字相似或宣传中提到 Agent，不能推导出兼容、替代或能力升级。分类的目的是找到可验证的技术问题。

## 八 · 练习与参考答案

### 练习

1. “Transformer 是监督学习，强化学习不属于深度学习。”这句话哪里混淆了分类轴？
2. 公司把 PDF 放进向量库，这一步已经完成 RAG 了吗？
3. 用同一个 LLM，能否分别搭建固定流程和 Agent？
4. 给这些词归类：NLP、SFT、Attention、RAG、Agent、Tokenization。

### 参考答案

1. Transformer 是架构，监督学习与强化学习是学习信号或范式。Transformer 可以用监督、自监督或强化学习等方式训练；深度神经网络也可以用于强化学习。
2. 没有。这是知识处理和检索基础设施的一部分。还要有问题检索、上下文组织、生成及质量验证等链路。
3. 可以。差别主要在系统如何控制执行路径和使用反馈，而不是必须换一个名字里带 Agent 的模型。
4. NLP 是任务领域；SFT 是监督微调方法；Attention 是计算机制；RAG 是应用架构模式；Agent 是这里讨论的运行系统；Tokenization 是文本与 Token 的处理过程。
