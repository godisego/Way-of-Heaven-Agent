# 项目案例：验证计划与证据记录

> 源码核对：2026-09-27。本页是验证规格，不是测试通过报告。前置：[评测与可观测性](/learn/agent-evaluation-observability)。学习目标：把需求变成可判定用例，并区分当前回归、人工评价和未来需求。

## 一 · 当前自动化门禁

首次安装或 lockfile 变化时执行 `npm ci`。提交前按改动运行相关测试，并完成项目门禁：

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

保存 commit、Node 与依赖版本、命令、退出码和实际输出。构建成功证明代码能构建，不能替代真实模型质量、检索效果或教学能力验证。

## 二 · 现有能力的回归规格

| 能力 | 固定输入或操作 | 应核对的证据 |
| --- | --- | --- |
| 入库 | PDF / Markdown / TXT 各一份；重复上传；embedding 失败后重试 | 来源单元与 chunk 坐标、去重、最终状态及错误原因 |
| 向量一致性 | 索引模型与查询模型不一致 | 明确不匹配错误与重建指引，不能混用向量 |
| 检索 | 标注正确来源的问题；指定库内书却无资料的问题 | 召回排名、来源与空结果路径；不假定有统一分数门槛 |
| 引用 | 真引用、假书名、假位置、真伪混合、越角色库引用 | 有效引用列表与违规原因；语义支持另做人工判断 |
| Agent | 脚本化 transport：搜索、读原文、收尾、重复调用、非法参数 | 工具次数、台账增量、停止原因、最终状态分别断言 |
| 时间边界 | 慢工具、慢调度模型、取消、生成阶段耗时 | 区分等待超时与底层取消；不把 90 秒当全请求硬截止 |
| 会话 | 两轮追问、刷新恢复、改名、删除；超窗口长对话 | 最近上下文、摘要持久化与删除结果；摘要不作为典籍证据 |
| 问者档 | 固定生辰与换日案例；伪造浏览器排盘字段 | 服务端重算与参考样例，记录换日、节气和算法口径 |
| 角色选择 | 全席与角色子集 | 只返回在席角色，符合对应顺序与资料范围 |
| 联网回退 | 库外普通问题、指定典籍问题、搜索失败 | 是否按条件回退，网页/模型知识与典籍来源标记清楚 |

读现有测试可从 `orchestrator.test.ts`、`toolRegistry.test.ts`、`contextBuilder.test.ts`、引用策略测试与 `scripts/acceptance.ts` 开始。上表是规格清单，具体覆盖情况仍要对照当前测试和运行结果；未执行的项目标“未执行”。

## 三 · 人工端到端核验

准备有权使用的少量典籍材料，记录文件哈希、embedding 模型、聊天模型及协议。固定一组问题，例如“怎么理解自欺，请给出处”“资料中是否包含某个不存在的章节”。

逐项记录：

1. 原文能打开，引用位置准确，正文结论得到该段支持；位置存在不够。
2. 资料不足时诚实说明限制；区分库内无据、检索故障和联网未核实。
3. 全席默认顺序老胡 → 李 → 玄；子集按选择验证，不能要求永远三段。
4. 查看工具轨迹，确认动作和停止原因可解释；不要求每次都走同一条合法路径。
5. 刷新能恢复会话，追问能使用上下文；删除会话后记录确实移除。
6. 注入材料不得获得额外权限；既看最终回答，也看工具调用和环境状态。

真实模型有随机性，应多次运行并报告样本数、失败与分群结果。一次成功演示不能代表长期成功率。

## 四 · 仍属于未来需求的验收

以下能力不能写成当前已通过：可查看编辑删除的跨会话长期记忆、可恢复后台任务、上传取消和进度完整闭环、多用户身份与数据隔离、写工具幂等恢复、全流程费用硬预算、完备风险分流与语义事实验证。

删除上传资料及其本地与云端衍生数据时，应先核查当次实现和覆盖范围；不能因为已有“删除会话”就认定文档级删除也完整。
