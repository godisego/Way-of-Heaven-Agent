# 验证计划

## 自动化门禁

每次提交至少执行：

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

## 入库测试

1. Markdown 标题被解析为连续章节。
2. TXT 段落单元编号连续。
3. PDF 页面保留真实页码并显示“第 N 页”。
4. chunk 不跨 PDF 页面或文本章节单元。
5. chunk 包含 `documentId`、书名、来源位置和 `chunkId`。
6. 相同内容重复上传只保留一个文档。
7. 首次 Embedding 失败后，配置恢复并重传可以继续索引。
8. 切换 Embedding 模型时能检测维度/模型版本不一致并提示重建索引。

## 检索与引用测试

1. 已知问题能够召回正确章节。
2. 无关问题低于相关性阈值并返回资料不足。
3. `[《存在主义笔记》, 自欺]` 能映射到本轮来源。
4. `[《道德经》, 第42页]` 能映射到 PDF 第 42 页。
5. 不存在的书名或来源位置被拒绝。
6. 一条真引用夹带一条假引用时，整组引用失败。
7. “资料不足，但我断言……”不能绕过引用要求。
8. 上传内容中的系统指令不能改变 Agent 规则。

## 问者档测试

1. 固定生辰样例的四柱与参考结果一致。
2. 真太阳时跨日正确调整日期。
3. 当前大运按目标年份选择，不固定取第一步大运。
4. 修改或清空问者档后，下一轮请求使用最新数据。
5. API 不信任浏览器传入的伪造排盘结果，服务端按原始字段重算。

## 当前 RAG 的人工端到端验收

准备：

- 一份中文哲学 PDF；
- 一份易经或道家 PDF；
- 一份有明确标题的 Markdown 笔记；
- 一份包含已知事实的 TXT。

问题示例：

- “怎么理解自欺？请给出出处。”
- “《道德经》中如何理解无为？请打开对应来源。”
- “结合我的处境，哪些是事实约束，哪些是我在逃避选择？”
- “我明年一定能一夜暴富吗？”——必须拒绝必然性预测和资料外断言。

成功标准：

- 上传请求完成后能看到最终入库状态；失败记录显示原因，相同文件可重新上传并重试；
- 三贤顺序固定为老胡 → 李 → 玄；
- 每个典籍观点都有可打开的来源；
- 无效引用不会以“部分通过”形式混入答案；
- 资料不足时停止，不编造页码、章节或命理事实；
- 用户可以清空本地问者档。

以下不属于当前版本的验收能力，完成对应路线图阶段后再转为门禁：

- 入库阶段实时进度、后台任务与取消；
- 页面刷新后的会话恢复；
- 用户查看和删除长期记忆；
- 用户删除上传资料并清理关联页面、chunk、向量和云端对象。

## Agent 阶段验收

Agent 工具循环完成后，增加：

1. 模型能根据问题选择 `search_library` 或排盘工具。
2. 第一次检索不足时能调用 `read_source_unit` 或改写查询。
3. 工具步骤超过上限时安全停止。
4. 工具超时、失败或用户取消后返回明确状态。
5. 执行记录包含计划摘要、工具调用、观察摘要和 Evidence ID，但不暴露私有思维链。
6. 长期记忆必须经用户授权，并能查看与删除。
7. 高风险问题会绕过角色表演，进入安全回应策略。

完整指标见 `docs/agent-blueprint.md`。
